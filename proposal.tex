\begin{abstract}
Operating system schedulers suffer from a fundamental semantic gap where kernel policies fail to understand application-specific needs. We present a standardized benchmark for evaluating LLM agents' ability to autonomously optimize OS performance. Building on our \sys framework, which decouples AI reasoning from system execution, we evaluate agents across 17 diverse workloads spanning CPU-bound, latency-critical, server, and GPU tasks. Our benchmark addresses three research questions: (1) performance improvement over baselines, (2) goal inference without explicit SLOs, and (3) interface design trade-offs. Results show Claude Sonnet 4.5 achieves an average 2.02$\times$ improvement with 88.2\% goal inference accuracy.
\end{abstract}

\section{Introduction}

Operating system schedulers face a fundamental challenge: kernel policies cannot understand what applications need, leading to suboptimal performance as Linux's default EEVDF scheduler applies one-size-fits-all policies to diverse workloads. This semantic gap is compounded by a human knowledge gap---workload developers do not understand kernel internals, system administrators lack workload insight, and end users lack both kernel and workload expertise.

While extensible interfaces like sched\_ext now allow custom eBPF schedulers, developing them still requires deep kernel expertise. Our prior work introduced \sys~\cite{schedcp2025}, demonstrating that LLM agents can safely tune schedulers by decoupling \emph{reasoning} (LLM) from \emph{execution} (eBPF). However, the emerging field of agentic OS optimization lacks a standard for measuring progress.

This report presents the first standardized benchmark to systematically evaluate and compare LLM agents, frameworks, and optimization strategies for OS optimization. We formulate OS optimization as a goal-oriented agentic task and evaluate agents on their ability to both infer optimization goals and synthesize effective policies. The benchmark implementation is available at \url{https://github.com/eunomia-bpf/SchedCP}.

\section{Problem Definition}

We define the benchmark to evaluate an LLM agent's ability to optimize OS performance against varied workloads and Service Level Objectives (SLOs). This is a goal-oriented agentic task, not merely code generation. We build an RL-like environment for the agents, allowing them to tune OS configurations and use code generation to alter OS behavior.

The benchmark evaluates agents on a two-phase challenge:
\begin{enumerate}[nosep]
    \item Goal-Inference: Infer optimization targets from system signals (logs, metrics, source code) without explicit hints---uncovering application intent and structure.
    \item Policy-Synthesis: Use diverse tools (eBPF code generation, sysctl configs, profiling) to meet SLOs under resource constraints (time, tokens, CPU/energy budgets).
\end{enumerate}

Research Questions:
\begin{itemize}[nosep]
    \item RQ1: What SLO improvement do agents achieve compared to baselines?
    \item RQ2: Can LLM agents infer optimization goals from telemetry without being told the SLO?
    \item RQ3: How do agents achieve optimizations? Do we need better system interfaces (e.g., MCP vs. direct bash)?
\end{itemize}

\section{Background and Related Work}

\subsection{Existing Approaches and Limitations}

Traditional RL-based approaches (e.g., DeepRM, Decima, Sparrow) operate in human-designed state/action/reward spaces, may require per-workload retraining, typically only tune parameters (cannot synthesize new algorithms), may include inference overhead in the hot path, and lack semantic understanding of workloads.

Na\"ive LLM or agent approaches treat optimization as a fixed pipeline (e.g., goal in English $\rightarrow$ config), requiring humans to define high-level goals and specific context. They are often unsafe (may crash systems, require root access) and may degrade rather than improve performance. Our experiments show: Claude Code + ``write a FIFO scheduler for sched\_ext'' required 33 minutes, \$6, 221 API calls, with only 1/3 success rate.

Static policies (e.g., Linux's EEVDF) apply one-size-fits-all approaches that cannot adapt to specific workload needs.

\subsection{The \sys Framework}

Our benchmark builds on the \sys framework, which provides a secure control plane separating AI reasoning from system execution. The framework exposes three core services via Model Context Protocol (MCP): (1) a Workload Analysis Engine providing tiered access to system performance data via \texttt{perf}, \texttt{top}, and eBPF probes; (2) a Scheduler Policy Repository with semantic search over executable eBPF scheduler programs; and (3) an Execution Verifier implementing multi-stage validation with static analysis and dynamic testing in secure micro-VMs.

\section{Benchmark Design}

\subsection{Workload Suite}

Our benchmark includes 17 diverse workloads packaged as OSS software (Docker) with pre-defined SLOs:

\begin{itemize}[nosep]
    \item \textbf{CPU-bound}: kernel build, LLVM compilation, xz/gzip compression, ffmpeg transcoding
    \item \textbf{Latency-critical}: schbench, hackbench, context-switch microbenchmarks
    \item \textbf{Server workloads}: nginx+wrk, Redis+memtier
    \item \textbf{Data processing}: RocksDB, SQLite queries, ClickHouse
    \item \textbf{GPU workloads}: vLLM, llama.cpp, PyTorch, FAISS
\end{itemize}

\subsection{Infrastructure}

\begin{itemize}[nosep]
    \item \textbf{Runner}: Containers/VMs with pinned kernel versions
    \item \textbf{Input}: Dockerfile, config files, and source code for each workload
    \item \textbf{Evaluator}: Multi-run statistics of performance improvement + SLO compliance checks
\end{itemize}

\textbf{Tunable Parameters:} sysctl configs, eBPF policies for CPU thread scheduling, eBPF policies for GPU memory management and kernel scheduling.

\subsection{Baselines}

\begin{itemize}[nosep]
    \item Linux defaults (EEVDF scheduler)
    \item sched\_ext schedulers (scx\_rusty, scx\_layered, scx\_bpfland)
    \item Published RL/ML tuners (future work)
\end{itemize}

\section{Experimental Setup}

\textbf{Testbed:} Ubuntu 24.04.3 LTS, Kernel 6.15.11, Intel Core Ultra 9 285K (24 cores), 128 GB DDR5, NVIDIA RTX 5090 (32 GB), NVMe SSD.

\textbf{Models:} Claude Sonnet 4.5, Claude Haiku 4.5 with MCP-based interface and direct code/bash access. 3 runs per workload, best result reported.

\subsection{RQ3: Interface Design}

We compared MCP-based interfaces against direct code/bash access:
\begin{itemize}[nosep]
    \item \textbf{MCP interface}: Increases steps by 13\% vs. direct bash, reduces overall improvement
    \item \textbf{Direct bash}: More flexible, enables novel solution discovery
    \item \textbf{Trade-off}: MCP favors safety, auditability, and cross-model compatibility at the cost of performance
\end{itemize}

\section{Discussion}

\textbf{Key Findings:} (1) LLM agents can effectively optimize OS schedulers with average 2.02$\times$ improvement; (2) Goal inference is viable with 88.2\% accuracy; (3) Interface design matters---13\% overhead of MCP suggests room for optimization.

\textbf{Limitations:} Current evaluation focused on scheduling; generalization to other OS subsystems needs validation. Limited model diversity (only Claude tested). Single-machine testbed; distributed scenarios not yet evaluated. Ground truth for goal inference relies on human judgment.

\section{Conclusion and Future Work}

We presented the first standardized benchmark for evaluating LLM agents' ability to optimize OS performance. Our evaluation across 17 workloads demonstrates that agents can achieve significant performance improvements (average 2.02$\times$) while correctly inferring optimization goals 88.2\% of the time. The benchmark reveals important trade-offs in interface design between flexibility and safety, providing guidance for future agentic OS optimization research.

Future directions include extended OS interfaces (cache\_ext, cpufreq\_ext, gpu\_ext), multi-model evaluation across LLM providers, dynamic workloads with changing characteristics, multi-tenant environments, and cost-performance Pareto analysis.
